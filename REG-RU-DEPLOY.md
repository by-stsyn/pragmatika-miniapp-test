# Размещение Mini App на Reg.ru

Целевой каталог: `/www/parts.pragmaticar.ru`

## Важно
Этот пакет — подготовительный перенос: frontend собирается GitHub Actions, а `/api/render` уже проксирует запросы на существующий Render. Остальные Vercel-функции пока возвращают HTTP 501 и должны быть перенесены до переключения пользователей. Не подключайте production-ботов к этой версии до завершения миграции и тестов.

## GitHub Actions secrets
В Settings → Secrets and variables → Actions добавьте:
- `REG_RU_HOST` — SSH host Reg.ru (имя сервера из панели хостинга)
- `REG_RU_USER` — `u1732467`
- `REG_RU_SSH_KEY` — приватный SSH-ключ, публичную часть которого добавьте в SSH-ключи Reg.ru
- `REG_RU_PATH` — `/www/parts.pragmaticar.ru`

Пароль от хостинга не нужен в workflow: используйте SSH-ключ. Не публикуйте пароль/ключ в чате, репозитории или файлах проекта.

## Первичная настройка
1. Загрузите содержимое проекта в GitHub-репозиторий и убедитесь, что основная ветка называется `main` (или измените workflow).
2. В Reg.ru проверьте, что `parts.pragmaticar.ru` привязан к каталогу `/www/parts.pragmaticar.ru`, включен HTTPS и доступен SSH.
3. Добавьте четыре GitHub Secrets выше.
4. Сделайте commit/push в `main`; в GitHub откройте Actions и проверьте выполнение.
5. После завершения миграции API проверьте URL `/api/render?path=...` и все функции приложения.

## Серверные секреты
Секреты Vercel не следует помещать в frontend или GitHub workflow. Их нужно задать на сервере в файле вне web-root (например, `/www/private/miniapp.env`, если такой каталог разрешён тарифом), с правами доступа только владельцу. Точные имена и значения следует сверить с Vercel перед переносом. PHP 7.4 не поддерживает `getenv()` из `.env` автоматически — приложение должно явно загрузить конфигурацию.
